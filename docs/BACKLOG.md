# بک‌لاگ و نقشه‌راه (Backlog & Roadmap)

این فایل فهرست کارهایی است که **هنوز کامل نشده‌اند یا نیاز به سرویس/اعتبارنامه‌ی
بیرونی دارند**. تا زمان مناسب اینجا می‌ماند و به‌ترتیب اولویت تکمیل می‌شود.

> وضعیت فعلی: هسته‌ی کسب‌وکار (CORE + ۱۴ ماژول)، بنل ادمین پلتفرم، ۲FA اجباری
> مدیران، و گیتینگ ماژول در زمان درخواست **تکمیل و تست‌شده** است.
> جزئیات: `docs/STATUS.md` · امنیت: `docs/SECURITY.md` · تست: `docs/TESTING.md`.

راهنمای نشانه‌ها: P0 = بحرانی/پیش‌نیاز تولید · P1 = مهم · P2 = ارزشمند · P3 = آینده.

---

## A) سرویس‌های بیرونی (منتظر خرید/اعتبارنامه)

کار نرم‌افزاری این‌ها آماده است؛ فقط provider واقعی و کلید اضافه می‌شود.

### A1. درگاه پرداخت واقعی (P0)
- [ ] پیاده‌سازی آداپتور «بنل» (سامانه شاپرک) مطابق `PaymentProvider`.
- [ ] فعال‌سازی زرین‌پال با `ZARINPAL_MERCHANT_ID` واقعی و تست sandbox.
- [ ] پشتیبانی از idpay (اختیاری) و **درگاه اصلی vs حالت دولوپر** به‌صورت هم‌زمان.
- [ ] تست E2E فلوی کامل: ایجاد پرداخت → ریدایرکت → callback → verify → تسویه.
- [ ] مدیریت refund در سطح درگاه (فعلاً refund داخلی است).
- مکان: `apps/api/src/modules/payments/providers/*`, `provider.registry.ts`

### A2. سرویس پیامک واقعی (P0)
- [ ] اتصال کاوه‌نگار / ملی‌پیامک در `SmsService` (اکنون فقط لاگ `console`).
- [ ] قالب‌های پترن (pattern) و مدیریت خطا/تلاش مجدد.
- [ ] گزارش تحویل و شارژ (بر پایه‌ی MSG-07 موجود).
- مکان: `apps/api/src/modules/notifications/sms.service.ts`

### A3. ایمیل واقعی (P1)
- [ ] تکمیل `sendViaSmtp` با nodemailer + اعتبارنامه SMTP.
- [ ] قالب‌های HTML و مدیریت bounce (اختیاری).
- مکان: `apps/api/src/modules/notifications/email.service.ts`

### A4. همگام‌سازی تقویم گوگل/اوتلوک (P1)
- [ ] دریافت OAuth2، ذخیره و تازه‌سازی توکن.
- [ ] sync دوطرفه‌ی رویدادها + webhook تغییرات.
- [ ] حل تعارض و سیاست خطا.
- مکان: `apps/api/src/modules/scheduling/` (اسکلت `CalendarConnection` موجود).

### A5. سامانه مودیان (FIN-09) (P1)
- [ ] امضای دیجیتال و ارسال الکترونیکی صورتحساب (نیازمند گواهی/شناسه حافظه مالیاتی).
- [ ] دریافت و ذخیره‌ی «شماره اقتصادی/شناسه یکتا».
- مکان: `apps/api/src/modules/finance/finance-extra.service.ts`

### A6. ذخیره‌سازی ابری S3 (P2)
- [ ] پیاده‌سازی درایور `s3` (اکنون فقط `local`).
- [ ] امضای URL، محدودیت حجم/نوع، و اسکن ویروس اختیاری.
- مکان: `apps/api/src/modules/files/`, `apps/api/src/config/configuration.ts`

## B) کارهای نرم‌افزاری باقی‌مانده (بدون نیاز به سرویس بیرونی)

### B1. پشتیبان‌گیری واقعی (CORE-06) (P0)
- [ ] تولید واقعی dump (pg_dump) در ورکر؛ اکنون فقط «رکورد متادیتا» ساخته
      می‌شود (`backups/.../*.dump` بدون فایل واقعی).
- [ ] زمان‌بند پشتیبان‌گیری دوره‌ای + prune ۳۰ روزه (متد `pruneBackups` موجود).
- [ ] مسیر بازیابی (restore) و آزمون بازیابی.
- مکان: `apps/api/src/modules/tenants/tenants-ext.service.ts`

### B2. تست E2E خودکار (P0)
- [ ] راه‌اندازی دیتابیس تست مستقل + اجرای مایگریشن/seed.
- [ ] تست E2E فلوی ۲FA ادمین (setup → confirm → login → verify → replay).
- [ ] تست E2E گیتینگ ماژول (grant/revoke → 403/200).
- مکان: `apps/api/test/` (اکنون فقط smoke زنده‌ی اختیاری وجود دارد).

### B3. تست فرانت‌اند (P1)
- [ ] افزودن Vitest + Testing Library به `apps/web` (اکنون هیچ تستی ندارد).
- [ ] تست کامپوننت‌های کلیدی: فرم‌ها، گاردهای ادمین، نمایش خطای `MODULE_DISABLED`.

### B4. CI/CD (P0)
- [ ] پایپ‌لاین GitHub Actions: `install → build → typecheck → test` روی هر PR.
- [ ] کش turbo + سرویس postgres/redis برای job تست.
- [ ] ساخت و انتشار ایمیج Docker (registry) روی tag.
- یادداشت: پوشه‌ی `.github/workflows` وجود ندارد.

### B5. آماده‌سازی تولید و استقرار (P0)
- [ ] Reverse proxy + TLS (nginx/traefik) و دامنه‌ها.
- [ ] `SECURE`/`SameSite` کوکی‌ها و تنظیم CORS دقیق در prod.
- [ ] مهاجرت با `prisma migrate deploy` در prod + بکاپ پیش از مهاجرت.
- [ ] Health/readiness/liveness و مانیتورینگ (Sentry/uptime).

### B6. طرح‌ها و سقف مصرف (P1)
- [ ] اجرای محدودیت‌های پلن در زمان درخواست (مثل گیتینگ ماژول): تعداد شعبه،
      کاربر، پیامک ماهانه، فضای ذخیره‌سازی.
- [ ] سنجش مصرف و اعلان نزدیک‌شدن به سقف.
- مکان: `apps/api/src/modules/admin/admin-plan.service.ts` (CRUD پلن موجود است).

### B7. لایه‌ی تخصصی صنفی (Layer 3) (P2)
- [ ] فیلدها/فرم‌های اختصاصی هر صنف (مثلاً پرونده درمانی، BOM رستوران و ...)
      به‌صورت افزایشی؛ قالب صنفی و ۱۷ دسته آماده است.
- مکان: `packages/shared/src/industries.ts`, `packages/shared/src/modules.ts`

### B8. مقیاس‌پذیری و چندسروری (P2)
- [ ] استخراج `tenantId` از زیردامنه/هددر (multi-domain) در صورت نیاز.
- [ ] جداسازی خواندن/نوشتن یا شاردینگ در سطح tenant برای حجم بالا.
- [ ] نرخ‌بندی توزیع‌شده (اکنون Throttler درون‌حافظه‌ای است؛ برای چند instance
      باید به Redis منتقل شود).
- مکان: `apps/api/src/app.module.ts` (`ThrottlerModule`)

### B9. Enforce ۲FA همه‌ی اعضای کسب‌وکار (P2)
- [ ] ۲FA اجباری برای نقش‌های حساس کسب‌وکار (OWNER/MANAGER) مطابق سیاست.
- زیرساخت TOTP مشترک موجود است (`TotpService`, `tenants-ext.service.ts`).

### B10. مستندات API و Onboarding (P2)
- [ ] غنی‌سازی Swagger (نمونه‌ها، شرح خطاها، دسته‌بندی کامل مسیرها).
- [ ] راهنمای راه‌اندازی تولید و runbook عملیاتی.

## C) بهبود کیفیت و پایداری

### C1. رشد پوشش تست (P1)
- [ ] تست سرویس‌های مالی (فاکتور/پرداخت/استرداد) و محاسبات مالیاتی.
- [ ] تست ماشین‌های وضعیت (سفارش، کمپین، اشتراک).
- [ ] تست ایزوله‌سازی چندمستأجری (نشت داده بین tenantها).

### C2. مشاهده‌پذیری (P1)
- [ ] لاگ ساخت‌یافته (pino) + همبستگی درخواست (request-id) در همه‌ی ماژول‌ها.
- [ ] متریک‌ها (Prometheus) و ردیابی (OpenTelemetry) اختیاری.
- [ ] داشبورد خطاها برای صف‌ها و زمان‌بندها (BullMQ).

### C3. امنیت و سختی‌سازی (P2)
- [ ] CSP سخت‌گیرانه‌تر + هدرهای امنیتی اضافه.
- [ ] چرخش کلید JWT و امکان ابطال گروهی.
- [ ] Rate-limit اختصاصی برای مسیرهای مالی حساس.

### C4. یکپارچگی داده (P2)
- [ ] قیدهای یکتایی/check در دیتابیس برای داده‌های حیاتی در صورت نبود.
- [ ] پاک‌سازی داده‌های منقضی (OTP/نشست‌های باطل/کدهای مصرف‌شده) با زمان‌بند.

## ترتیب پیشنهادی تکمیل

1. **B4 (CI)** و **B1 (پشتیبان‌گیری واقعی)** — پیش‌نیاز عملیات مطمئن.
2. **A1/A2 (درگاه و پیامک واقعی)** — به‌محض تهیه‌ی اعتبارنامه.
3. **B5 (استقرار تولید)** + **B2 (E2E)** — همراه با اولین انتشار واقعی.
4. **B6 (سقف پلن)** و **B3 (تست فرانت)** — رشد محصول.
5. **A4/A5 (تقویم/مودیان)** و **B7 (لایه‌ی صنفی)** — توسعه‌ی بازار.
6. **B8/B9/C2 (مقیاس‌پذیری، ۲FA اعضا، مشاهده‌پذیری)** — با رشد کاربران.

> هر بار که موردی تکمیل شد، آن را از این فایل حذف یا به `docs/STATUS.md` منتقل کن.
